6. Rebuild procedure — raw EC2 → working replica

  1. Launch per Spec §7 step 1; create the tunnel and DNS per step 2.
  2. scp the three hand-over files to /tmp on the box.
  3. Run bootstrap.sh with REPLICA, ZONE, TUNNEL_UUID, ACCESS_KEY (and NIM_BEARER if nimN.<zone> is published).
  4. Wait for nemotron-lightning and embedqa to report ready (first start downloads ~70 GB: 10–20 minutes).
  5. The seeder (milvus-seeder) runs once from the blueprint's compose; confirm a search returns products.
  6. Validate per Spec §8; capture the Lab 1 screenshots (docker compose ps, nvidia-smi, Phoenix).

8. Known issues and gotchas

  • Compose resolves the overlay's relative paths against the blueprint directory — which is why the overlay uses ${WORKSHOP_DIR} everywhere. Do not "fix" the paths to be relative.
  • The overlay's devices: !override needs Docker Compose ≥ 2.24 (docker compose version); older versions append the blueprint's GPU 1 reservation and the embed NIM fails on a one-GPU box.
  • env_file entries must exist before docker compose up; an empty .env.workshop starts the agents without exporters and they log a warning per exporter rather than failing.
  • Both nvidia-nat exporters are registered by nvidia-nat-opentelemetry; nat info components -t telemetry_exporter inside an agent container lists galileo and otelcollector if the image is intact.
  • The AI Defense gateway must be able to reach the NIM. With the hosted gateway that means publishing nimN.<zone> behind the Caddy bearer check; with the local gateway profile nothing is published.
