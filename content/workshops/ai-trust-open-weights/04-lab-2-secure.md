## Background

Agent Security is a live integration: it inspects the prompt (pre-LLM) and the response (post-LLM) against **multiple guardrails** and blocks non-compliant content. The **Prescriptive Overreach** evaluator measured in [Lab 1](/workshops/ai-trust-open-weights/03-lab-1-measure/) is enforced here as a **custom guardrail** on both prompts and responses.

## Labs

### Lab 2.1 Prompt Prescriptive Overreach in PseudoCo Assistant

#### 2.1.1 Access PseudoCo Assistant

Return to the tab with PseudoCo Assistant. If you closed it, access it from the splash page.

![alt text](/workshops/ai-trust-open-weights/image.png)

Click **Open PseudoCo Assistant**.

#### 2.1.2 Prompt Prescriptive Overreach

![alt text](/workshops/ai-trust-open-weights/image-33.png)

Open the left side-panel, make sure **Cisco AI Defense Policy Review** is off, and toggle **Include Toxic Content in Responses** and **Prescriptive Overreach** on, then send any prompt.

![alt text](/workshops/ai-trust-open-weights/image-34.png)

A very non-compliant response should be received - that's not good!

### Lab 2.2 Review Current Policies in Agent Security

#### 2.2.1 Access Agent Security

![alt text](/workshops/ai-trust-open-weights/image-35.png)

On the splash page, click **Execute** below **Cisco Cloud Control**.

![alt text](/workshops/ai-trust-open-weights/image-36.png)

Click the nine dots in the upper left corner.

![alt text](/workshops/ai-trust-open-weights/image-37.png)

Click **Agent Security** under **Apps**. Cisco AI Defense is also known as Agent Security.

Ensure you do not click on **Agentic Security**.

#### 2.2.2 Review Dashboard

![alt text](/workshops/ai-trust-open-weights/image-38.png)

Cisco Agent Security dashboard providing a centralized view of discovered AI agents, MCP servers, models, activity, and security findings across the environment.

**Agent inventory:** Shows the total number of discovered AI agents and separates registered enterprise agents from endpoint and SaaS agents.<br>
**Agent activity:** Provides a consolidated view of active agents, including registered and discovered agents across the environment.<br>
**MCP servers:** Lists discovered MCP servers connected to the environment and shows the total number identified.<br>
**Agent findings:** Summarizes detected security risks across MCP servers, including severity and the number of affected systems.<br>
**Attack techniques:** Highlights observed techniques such as direct prompt injection, data exfiltration or exposure, and tool exploitation.<br>
**Models and skills:** Shows the AI models and agent skills associated with the discovered environment.<br>
**Enterprise agent events:** Tracks the volume of security-relevant events generated by enterprise agents.

#### 2.2.3 Review Prescriptive Overreach Guardrail

![alt text](/workshops/ai-trust-open-weights/image-39.png)

Click on **Policy -> Adaptive Guardrail Profiles**.

![alt text](/workshops/ai-trust-open-weights/image-40.png)

Click on **Prescriptive Overreach**.

![alt text](/workshops/ai-trust-open-weights/image-41.png)

Cisco Agent Security Policy Studio showing how a natural-language policy is translated into enforceable AI guardrails, evaluated against test cases, and refined over multiple versions.

**Policy definition:** The policy blocks prescription-drug recommendations and dosing instructions while allowing OTC-safe guidance, self-care advice, and referrals to licensed professionals.<br>
**Policy Studio Assistant:** The assistant interprets the requested policy, identifies the intended violation criteria and exclusions, and generates the corresponding policy profile.<br>
**Versioning and status:** Shows the current policy version, change history, and whether the policy has been approved or published.<br>
**Evaluation:** Measures policy performance against sample interactions, including accuracy and supporting evaluation metrics.<br>
**Policy overview:** Breaks behavior into violations, safe behaviors, and edge cases to make enforcement boundaries explicit.<br>
**Flags:** Defines behavior that should trigger enforcement, including personalized prescription recommendations, prescribing actions, prescription-style dosing, and controlled-substance guidance.<br>
**Allows:** Defines acceptable behavior such as OTC-safe dosing, supplements, lifestyle guidance, general health education, adherence support, and referrals to professionals.<br>
**Edge cases:** Captures ambiguous scenarios that require more precise handling so the policy does not over-block legitimate responses.

Click on **View source text**.

![alt text](/workshops/ai-trust-open-weights/image-42.png)

The source text is the specific instructions that Agent Security uses to secure the agentic turn.

### Lab 2.3 Apply Prescriptive Overreach Guardrail

#### 2.3.1 Access PseudoCo Assistant

Return to the tab for PseudoCo Assistant. If you closed it, access it from the splash page.

![alt text](/workshops/ai-trust-open-weights/image.png)

Click **Open PseudoCo Assistant**.

#### 2.3.2 Prompt Prescriptive Overreach

![alt text](/workshops/ai-trust-open-weights/image-43.png)

In the left side-panel, toggle on **Cisco AI Defense Policy Review**, **Include Toxic Content in Responses**, and **Prescriptive Overreach**, then click **New Session**.

![alt text](/workshops/ai-trust-open-weights/image-44.png)

Send any prompt. This time the response is withheld, so the non-compliant output never reaches the user.

#### 2.3.3 Review the Event in Agent Security

![alt text](/workshops/ai-trust-open-weights/image-47.png)

Return to the tab for Agent Security.

![alt text](/workshops/ai-trust-open-weights/image-48.png)

Click on **Events -> Enterprise Agent Events**.

![alt text](/workshops/ai-trust-open-weights/image-49.png)

The **Event Logs** page opens. Open the **Application / MCP Server** filter.

![alt text](/workshops/ai-trust-open-weights/image-50.png)

Select **PseudoCo-App**, not PseudoCo-AI. Then click the most recent event where **Rule action** is **Block** and **Message type** is **Response**.

![alt text](/workshops/ai-trust-open-weights/image-51.png)

You can review the details of why the turn was blocked.

## Outcome

A risky medical response went from **non-compliant to trusted**. The unsafe output never reached the user; the guardrail was defined in plain language in Policy Studio; the fix was validated against the live app and traced in Agent Security.

- **Threats are stopped, not just seen.** Agent Security inspects every prompt and every response, and blocks what crosses the line in real time.
- **Trust is a runtime control.** Policy is written and tuned the moment a gap appears — not filed as a quarterly change request.
- **Measure and enforce are one loop.** The Lab 1 evaluator became the guardrail.
